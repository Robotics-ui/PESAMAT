# 1. Platform Settings Module

Create a configurable Platform Settings module instead of hardcoding values.

Create a new table:

system_settings

- id
- setting_key
- setting_value
- updated_at

Store configurable settings such as:

- FREE_TRIAL_DAYS
- TRIAL_ENABLED
- PHONE_VERIFICATION_REQUIRED
- AUTO_ASSIGN_MASTER
- AUTO_BIND_AFTER_VERIFICATION
- VIP_MONTHLY_PRICE
- PRO_MONTHLY_PRICE
- MAX_USERS_PER_MASTER
- MASTER_RESERVED_CAPACITY_PERCENT
- AUTO_REBALANCE

Provide secure ADMIN-only APIs:

GET /api/admin/settings

PUT /api/admin/settings

All settings must be read dynamically by the application without requiring redeployment.

# 3. Trial Subscription Flow

After:

- Successful registration
- Successful phone verification

Automatically:

- Read FREE_TRIAL_DAYS from system_settings
- Create a TRIAL subscription
- Activate the subscription
- Calculate expiry date
- Bind the user to a Distribution Master only if AUTO_ASSIGN_MASTER is enabled

Never hardcode trial duration.

# 5. Intelligent Load Balancer

Upgrade the Load Balancer Worker.

Instead of assigning users based only on the least-loaded master, calculate a Health Score using:

- Current load
- Capacity
- Latency
- Online status
- MetaApi connection health
- Replication delay

Assign new subscribers to the highest-scoring healthy Distribution Master.

Never exceed:

Maximum Capacity − Reserved Capacity

Example:

Capacity = 2500

Reserved Capacity = 10%

Maximum Assignable Users = 2250

This leaves spare capacity for reconnects and unexpected spikes.
